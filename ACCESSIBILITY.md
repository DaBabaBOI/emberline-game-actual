# Accessibility

Emberline aims to make its strategy game and project information usable by as many people as possible. Accessibility is ongoing work, and reports about barriers are welcome. This statement describes the current experience; it is not a claim of WCAG conformance.

## Supported environments

Emberline is a browser-based project designed for current desktop and mobile browsers. The game is laid out for laptops and touch phones. We do not currently publish a tested browser and assistive-technology compatibility matrix, or guarantee support for every browser/device combination.

## Available features

The Accessibility control is on the project page and outside active gameplay; in a game, open Menu and then Accessibility. The settings include:

- Pixel, sans-serif, and serif font choices
- Dark mode and high contrast
- Larger text
- Overall sound volume; the in-game Sound menu also has separate music and effects/ambience levels and a mute control
- Reduced animation when the operating system or browser requests reduced motion

The game supports mouse input and touch layouts. Some actions also have keyboard controls, including moving a picked-up villager with the arrow keys or WASD. The project page and game interface use labeled controls in many places.

## Known limitations

- The 3D map is primarily visual and is not yet fully operable or understandable with a keyboard or screen reader. Many map actions rely on pointing, tapping, or interpreting the scene.
- Some information is conveyed through color, animation, or pixel-sized detail. High contrast, reduced motion, and larger text help in parts of the interface but do not remove every barrier.
- Accessibility has not had a formal WCAG audit, and the project does not yet maintain a verified screen-reader or assistive-technology support matrix.

## Report a barrier

Open a [bug report](https://github.com/DaBabaBOI/shistech-hackathon/issues/new?template=bug_report.yml) for a barrier in the current experience, or a [feature request](https://github.com/DaBabaBOI/shistech-hackathon/issues/new?template=feature_request.yml) for an improvement. Start the title with `[Accessibility]` and include, when possible:

- What you were trying to do and what happened
- What you expected to happen
- Browser, operating system, and device
- Assistive technology and relevant settings, if used
- Steps to reproduce the barrier

You can omit personal or medical information. If you cannot use the issue forms, contact a repository maintainer through GitHub. For security vulnerabilities, use the private process in [SECURITY.md](SECURITY.md) instead.
