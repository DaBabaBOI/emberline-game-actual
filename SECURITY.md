# Security Policy

## Supported versions

The project is actively developed and the latest version in the default branch is
considered the supported version for security updates.

## Reporting a vulnerability

Please do not report security vulnerabilities through public issues or pull
requests. Instead, use GitHub's private security advisory flow for this repository.

If the repository does not yet have a published security advisory, open a private
report through the repository security tab and include:

- a clear description of the issue
- affected file(s) or route(s)
- reproduction steps if available
- severity and impact assessment
- any suggested mitigation or fix

## Response expectations

We will review valid reports as quickly as possible and aim to provide an initial
response within a reasonable timeframe. We may ask for additional information if
needed.

## Safe disclosure guidance

Please avoid disclosing the vulnerability publicly until we have had a chance to
review and patch it.

## Scope

This policy applies to security issues in the project codebase, build setup, and
deployment configuration that could lead to harm, data exposure, or application
breakage.
